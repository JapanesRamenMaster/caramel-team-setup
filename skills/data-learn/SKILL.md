# /data-learn

데이터 작업 완료 후 새로 알게 된 DB/쿼리 지식을 레퍼런스 문서에 반영하는 스킬.
Use when: "data-learn", 데이터 작업 마무리 후, 쿼리 작업 끝나고 문서 반영할 때.
사용자가 명시적으로 호출하거나, 데이터 작업이 끝난 뒤 새로 발견한 게 있으면 자발적으로 제안할 것.

## 실행 흐름

### 1단계: 이번 대화 리뷰

이번 대화에서 수행한 데이터 작업을 리뷰한다:
- 어떤 테이블을 사용했나
- 어떤 JOIN/필터 패턴을 썼나
- 예상과 달랐던 데이터 동작이 있었나
- 삽질/재작성의 원인이 무엇이었나

### 2단계: 새 발견 추출

기존 레퍼런스 문서에 **없었던** 지식만 추출한다:

- `QUERY_REFERENCE.md` 읽기
- `grafana-audit/caramel_de_schema_updated.md` 관련 부분 읽기

다음 중 해당하는 것만 추출:
- **필터 함정**: 특정 필터의 실제 동작이 직관과 다른 경우
- **테이블 동작 방식**: 컬럼의 실제 용도가 이름/문서와 다른 경우
- **데이터 특성**: 특정 컬럼의 NULL 비율, 실제 값 분포 등
- **코드-DB 연동**: 코드에서 특정 테이블을 어떻게 사용하는지 (슬롯 생성 로직 등)
- **쿼리 패턴**: 특정 분석에 필요한 JOIN 패턴, 주의사항

다음은 제외:
- 이미 문서에 있는 내용
- 이번 작업에만 해당하는 일회성 정보
- 특정 날짜의 데이터 값 (시간이 지나면 stale)

### 3단계: 반영 대상 분류 및 제안

추출된 각 항목을 분류:

| 분류 | 반영 대상 | 예시 |
|------|----------|------|
| 쿼리 규칙/함정 | `QUERY_REFERENCE.md` | 필터 기준, off 판단 로직, 테이블 간 관계 |
| 스키마 특성 | `caramel_de_schema_updated.md` | 컬럼 실제 용도, 데이터 특성 |
| 해당 없음 | skip | 이미 문서화됨, 일회성 |

### 4단계: diff 제시 및 반영

각 반영 대상에 대해:
1. 문서의 어디에 추가할지 (섹션 지정)
2. 추가할 내용 (간결하게, 기존 문서 스타일에 맞춰)
3. 사용자 확인 후 Edit으로 반영

## 규칙

- 기존 문서의 톤/구조를 유지할 것 (불릿 포인트, 볼드 키워드, 코드 블록)
- 과도하게 상세한 설명 금지 — 다음에 쿼리 짤 때 "이거 조심해야지"라고 떠올릴 수 있는 수준
- 반영할 게 없으면 "새로 반영할 내용 없음"으로 종료
- 반영 완료 후 변경 내용을 한 줄씩 요약
