# 안전 액션 레이어 (Safe Action Layer) — 설계

작성: 2026-06-16 · 상태: 설계 확정(구현 플랜 대기)

## 목표

비개발자 팀원이 **unknown unknown(자기가 뭘 모르는지도 모르는 상태)이 있어도, 사고 치지 않고, 의도대로, 자연어로** 작업하게 한다. AI로 누구나 쿼리·DB 조작이 쉬워지면서 prod 직접 조작 사고가 늘어난 것이 출발점(2026-06-15 더현대 행사 예약 DB 직접 INSERT 사고).

목표는 "SQL/위험 작업 금지"가 아니다. **위험만 막고 나머지는 자유롭게** 두는 것이다.

## 핵심 메커니즘 — 자가성장 루프

팀원이 자연어로 *뭐든* 시도하면, 위험 행동은 실행 직전 가드가 가로채 **막고 + 승인된 스킬/API로 유도**한다. 대안이 아직 없으면 그 시도 자체를 "만들어달라" 요청으로 전환한다.

```
팀원 자연어 작업
   │
   ▼
클로드가 액션 시도 ──→ 가드(PreToolUse 훅)가 검사
   │                        │
   │                  위험한가?
   │            ┌───────────┴───────────┐
   │          아니오                    예
   │            ▼                        ▼
   ▼          통과                 승인된 대안 있나?
 통과                        ┌────────┴────────┐
                            있음              없음
                             ▼                 ▼
                   "이 스킬/API로 하세요"   "위험하고 아직 안전한
                      (차단 + 유도)          방법이 없음 → 요청 등록"
                                              │
                                              ▼
                                  incoming 큐 → 개발자가 스킬/API 생성
                                              │
                                              ▼
                                  카탈로그 등록 → 다음엔 '대안'으로 자동 제시
```

화이트리스트는 "모르는 상황"에서 막히고, 단순 차단은 "의도"를 못 이룬다. 이 루프는 **unknown unknown이 차단될 때마다 그걸 새 액션 요청으로 바꿔, 시스템이 스스로 똑똑해진다.** 사고는 막고, 막힌 건 곧 다음 기능이 된다.

## 확정된 설계 결정

| 결정 | 선택 | 이유 |
|---|---|---|
| 1차 방어선 | **실행 시점 가드레일** | 자유도를 죽이지 않으면서 unknown unknown을 막는 유일한 위치. 사람이 몰라도 위험 행동 자체를 가로챔 |
| 차단 후 동작 | **차단 + 안전한 대안 유도** | 막으면서 의도를 이루게 함. 가드레일과 액션 카탈로그가 한 몸이 됨 |
| 접근 방식 | **하이브리드(A→B)** | 로컬 훅(넓고 얕게)으로 지금 사고 줄이고, prod write는 계정·API 강제(좁고 깊게)를 점진 구축 |
| 준수 보장 | **세팅 게이트(차단형)** | 팀원이 좀 불편해도 확실성이 더 중요. 가드 꺼진 채 작업 시작 자체를 봉쇄 |
| 실패 정책 | **fail-closed(의심스러우면 막음)** | 확실성 우선. 오탐은 빠른 예외요청 경로로 푼다 |

## 구성요소 6개

대부분 이미 존재하는 인프라를 잇는다. 진짜 신규는 #2와 #6.

| # | 구성요소 | 하는 일 | 현재 상태 |
|---|---|---|---|
| 1 | 가드 훅 | PreToolUse에서 위험 행동 감지 → 차단 + 대안 안내 | db/git-guardrail 있음 → "대안 유도" 추가 |
| 2 | 위험→대안 매핑 | "prod 예약 INSERT 패턴 → `예약-생성` 스킬" 룩업 | 신규 (작은 룰 테이블) |
| 3 | 액션 카탈로그 | 승인된 스킬/API 목록 = 대안의 출처 | 있음 (caramel-skills-catalog) |
| 4 | 요청 큐 | 대안 없는 위험 → "만들어달라" 자동 등록 | 있음 (incoming) → 가드와 연결 |
| 5 | 전파·자가복구 | team-setup이 가드·설정을 설치하고, 빠지면 복구 | 있음 (update.sh `ensure_hook`) → 가드까지 확장 |
| 6 | 준수 가시성(하트비트) | 세션 시작 시 세팅상태 점검→게이트+중앙 기록→현황판 | 신규 (team-diagnose를 자동·중앙화) |

## 데이터 흐름

**세션 시작 (게이트):**
```
SessionStart 훅 → 자가체크(가드 ON? 버전 최신? 카탈로그 동기화?)
      │
 정상 ─→ 작업 허용 + 하트비트 기록(🟢)
 미달 ─→ 자가복구 시도 ──성공─→ 작업 허용
                       └─실패─→ 작업 차단 + 메인테이너 알림(🔴)
```

**작업 중 (런타임 가드):** 매 액션마다 PreToolUse 가드 → 위험? → (대안 有)차단+유도 / (대안 無)요청큐 / (안전)통과.

## 메인테이너 현황판 + "쓰는 중 = 정상" 불변식

세팅 게이트 때문에 **깨진 채로는 작업을 시작조차 못 한다.** 따라서 **"하트비트가 찍혔다 = 게이트를 통과했다 = 정상이었다"**가 자동 성립한다. "깨진 채 모르고 쓰는" 시나리오가 구조적으로 불가능해진다.

| 팀원 상태 | 현황판 | 의미 |
|---|---|---|
| 오늘 하트비트 있음 | 🟢 시각+버전 | 정상 보장(게이트 통과) |
| 오늘 하트비트 없음 | ⚪ 미사용 | 클로드 안 켬 — 리스크 아님 |
| 게이트 차단됨 | 🔴 즉시 알림 | 세팅 깨짐 → 작업 막힘 + 호출 |

현황판 예시:
```
팀 안전세팅 현황                     (자동 갱신)
🟢 심형석   09:12  v6  가드ON  위반0
🟢 강희준   09:40  v6  가드ON  위반0
🔴 노진우   ──     v4  ❌게이트차단(버전stale, 자가복구 실패)
⚪ 오태진   어제    ─   (오늘 미사용)
오늘 활성 3명 중 정상 2 · 주의 1
```

**구현 위치(MVP)**: 하트비트는 중앙 저장(Google Sheet 한 장 or KV)에 한 행씩 → 조회는 슬랙 슬래시 커맨드(`/팀세팅현황`) 또는 카탈로그 사이트(the-trive Vercel) "팀 현황" 탭.

## 위험→대안 매핑 운영

시스템의 생명줄. 운영 주체를 명확히 한다.
- **개발자(디테일러)가 PR로 관리** — 새 위험 패턴·대안은 team-setup PR로(기존 스킬 PR 큐와 동일 흐름).
- **자가성장 루프가 후보 자동 공급** — 요청 큐(#4)에 쌓인 "막혔는데 대안 없던 케이스"가 곧 "다음에 추가할 매핑" 목록. 사람은 검토·승인만.
- 매핑도 카탈로그처럼 validate 대상(stale/오류 매핑이 잘못된 스킬을 안내하지 않도록).

## 실패 정책 (확실성 우선)

| 상황 | 정책 |
|---|---|
| 위험 판정이 애매 | 막는다(fail-closed). 오탐 감수 + 빠른 예외요청 경로 |
| 가드 훅 크래시/예외 | 위험 액션 차단(안전) + 즉시 메인테이너 알림 + 복구 |
| 대안 매핑 stale/오류 | validate 대상으로 관리 |
| 하트비트 중앙기록 네트워크 실패 | 작업은 진행(가드는 로컬이라 독립), 기록만 best-effort 재시도 |

## 로드맵

**A단계 (지금~수주, 인프라 있음 → 바로):**
- 가드 훅에 "차단 + 대안 유도"(#1+#2)
- 대안 없으면 incoming 요청 큐로(#4) = 자가성장 루프 완성
- 준수 하트비트 + 세팅 게이트 + 현황판(#6)
- team-setup으로 전파 + 자가복구(#5)

**B단계 (인증 secret1 정비 후):**
- prod write 권한을 계정에서 회수(raw 우회 차단 = 단단한 바닥)
- 승인된 액션은 API 경유 강제 + 호출자 감사 추적

## 신뢰 경계 (정직한 한계)

A단계 로컬 훅은 **작정하고 게이트+하트비트를 통째로 떼면** 우회 가능하다. 이는 "악의 없는 실수"가 아니라 명백한 우회이며, 평소 쓰던 사람의 하트비트 끊김이 그 자체로 알림 신호가 된다. 진짜 강제(못 떼게)는 B단계 계정 권한이 바닥에서 잡는다.
